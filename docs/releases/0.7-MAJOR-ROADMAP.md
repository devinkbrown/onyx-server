# Onyx 0.7 — major-release roadmap

**Version stays `0.7.0`.** This is not a later train. 0.7 is the extremely
major release: portable performance, per-OS kernel features, a hardened Armor
TLS toolkit, IRCX that a client actually lives in, expanded IRCX on the
daemon, and a harden / correctness pass that treats the wire as hostile.

**Audience:** contributor and maintainer.
**Repos:** Onyx Server (`/home/kain/onyx-server`) and Onyx (`/home/kain/onyx`).
**Companion plans this document expands, not replaces:**
[`0.7-RELEASE-PLAN.md`](0.7-RELEASE-PLAN.md),
[`../FEATURE-ROADMAP.md`](../FEATURE-ROADMAP.md),

**Client IRCX slice:** [`../../../onyx/docs/ROADMAP-0.7-IRCX.md`](../../../onyx/docs/ROADMAP-0.7-IRCX.md).

## 1. Thesis

0.5.x grew capability (Armor TLS, Undertow, Helix, IRCX verbs, media). The
original 0.7 plan then *stopped growing outward* and asked for measurement,
upgrade safety, and a classified exploit corpus. That plan stands — and it is
no longer enough for the release we are cutting.

**0.7 now ships as a major product release**, still numbered 0.7.0:

| Track | Prefix | One-sentence goal |
| --- | --- | --- |
| Original 0.7 blockers | P0-0…P0-6 | Helix 0.5.8→0.7 bridge, benches, ownership-safe io flags, DST, TLS harden, exploit inventory, version drift. |
| **Portable performance** | **PX** | One daemon contract on Linux (Ringlane / io_uring), Windows (IOCP), and BSD/macOS (kqueue), measured on each. |
| **Kernel unique features** | **KX** | Take each kernel's real advantages (Linux io_uring/kTLS/Landlock/eBPF-reuseport; FreeBSD KTLS+Capsicum+`SO_REUSEPORT_LB`; OpenBSD pledge/unveil; Windows IOCP/RIO) without pretending they are portable. |
| **Armor TLS + CLI** | **AX** | Unstub security-critical `armor` verbs; leftover TLS policy stays fail-closed; CLI and ACME worker sandboxed per-OS. |
| **Expanded IRCX (daemon)** | **IX** | Close the draft-and-legacy gaps that still leave IRCX a verb list rather than a complete conversation plane. |
| **Client IRCX adaptation** | **CX** | Onyx uses IRCX as its native room model — LISTX, MODEX, WHISPER, PROP, ACCESS, EVENT — not IRC with a few extras. |
| **Harden / correctness** | **HX** | Hunt exploitable paths, fail closed, add rejection tests, polish the correctness bar. No “looks fine.” |

A 0.7 that only lands the original P0 table is a stabilization tag. A 0.7 that
lands these tracks is the major release.

## 2. What is already true (do not rebuild)

Verified against live source at the time of writing. Re-check before dispatch.

### Daemon IRCX that already exists

Registered in `src/daemon/modules/ircx.zig`: `IRCX`, `ISIRCX`, `DATA`,
`REQUEST`, `REPLY`, `WHISPER`, `PROP`, `ACCESS`, `SACCESS` (oper), `AUTH`,
`EVENT`, `MODEX`, `LISTX`. `CREATE` and `KNOCK` live in `channel_ops`.
Persistent gag is `MODE +z` / `gag_set.zig`, not a standalone `GAG` verb.
Draft `WALLOPS` is `EVENT BROADCAST` (no `+w` umode). OPER is disabled
(`491`); elevation is SASL.

Reference: [`../reference/ircx/README.md`](../reference/ircx/README.md),
[`../reference/commands/ircx.md`](../reference/commands/ircx.md).

### Client IRCX that already exists

- Connect path sends `IRCX` (`src/lib/irc/client.ts`).
- Store folds PROP (818/819 + live `PROP`), ACCESS (801–805), WHISPER inbound,
  encryption / history / AI / pins / watch / topics / stage props.
- Channel settings expose ACCESS under Advanced (`ChannelSettings.tsx`).
- Oper desk drives `EVENT` ADD/DEL/LIST/BROADCAST/OBSERVE (`operDesk.ts`).
- `isIRCX` gates registry and history-policy wait.

**Thin or missing on the client:** LISTX browser, MODEX named-mode UI,
WHISPER compose (inbound only), SACCESS operator UI, auditorium (`+x`)
member-visibility, DATA/REQUEST/REPLY product surface, IRCX-first discover
(users still meet IRC MODE letters first).

### Performance / platform that already exists

- Production hot path is Linux `LinuxServer` + inline io_uring in
  `src/daemon/server.zig`. kTLS is Linux-only and default-off
  (`src/daemon/ktls.zig`, `[tls] ktls=off|tx|txrx`).
- `src/substrate/platform.zig` already funnels clocks / entropy / pid for
  Linux, Windows, and BSD/macOS. That is **not** a portable reactor.
- `src/substrate/io/ring.zig` is an **unfinished prototype** (no connect /
  poll / cancel, no kernel PBUF). Do not adopt it as the Windows/BSD backend.
- `zig build bench` exists (offline micro-harness). Live-daemon axes
  (TLS mode, shard count, `ring_entries` × `cqe_batch`, JOIN+PRIVMSG RTT,
  RSS) are `zig build bench-live` / `tools/bench.sh --live`.
- Multishot recv and provided-buffer rings stay **deferred**: they rewrite
  Helix buffer ownership. A major 0.7 does not buy that rewrite.

## 4. Track PX — portable performance (Linux / Windows / BSD)

**Goal:** the same IRCX + mesh + Armor contract runs, and is measured, on
three kernels. Linux keeps Ringlane. Windows and BSD get a **first-class
portable I/O backend**, not a “best-effort `#ifdef`.”

Production today is Linux-only for the accept/recv/send/poll/timeout loop.
`platform.zig` already isolates clocks and entropy; PX extends that mandate
to the reactor.

| ID | Item | Owner | OS | Gate |
| --- | --- | --- | --- | --- |
| **PX-0** | **I/O backend trait.** One `IoBackend` (or equivalent) that the daemon drives for accept / recv / send / poll / cancel / timeout. Linux implementation is the existing shadow ring (not substrate `ring.zig`). Windows and BSD implementations compile and fail closed on unimplemented ops. | `onyx-server-reactor` | all | `zig build check` on `x86_64-linux`, `x86_64-windows`, `x86_64-freebsd` (or the project’s current cross triples) |
| **PX-1** | ◐ **PARTIAL (2026-09-04).** `io.defer_taskrun` / `io.sqpoll` parse + project onto `Loaded.io` and `server.Config.features`. `RingCore.init` is the fail-closed kernel probe (no silent narrow). Do not raise `cqe_batch` without a P0-1 before/after. Live bench recipe exists (`zig build bench-live`); capture an idle artifact before using it as a floor. | `onyx-server-perf` | linux | `zig build test-config && zig build test-server && zig build bench && zig build bench-live -- --quick` |
| **PX-2** | **Windows IOCP backend.** Completion-port loop that preserves Helix quiesce (cancel-by-`user_data`, no kernel write into a successor page). No kTLS; userspace Armor only. | `onyx-server-reactor` | windows | Cross-compile + focused IOCP unit tests; skip Linux-only io_uring tests |
| **PX-3** | **BSD / macOS kqueue backend.** Same contract as PX-2. `EVFILT_READ/WRITE` + timers. | `onyx-server-reactor` | freebsd, netbsd, openbsd, macos | Cross-compile + kqueue unit tests |
| **PX-4** | **Portable Helix handoff.** `memfd` / `USR2` stay Linux. Windows/BSD get a documented cold-upgrade or equivalent inherited-socket story that does **not** pretend USR2 exists. Fail closed if a Linux-only capsule path is reached. | `onyx-server-helix-reviewer` · `zig-coder` | win/bsd | `zig build test-helix` + explicit skip/fail tests on non-Linux |
| **PX-5** | **Per-OS bench artifacts.** Same `zig build bench` harness plus a live-daemon recipe per backend. Publish numbers in `docs/dev/benchmarks.md` with OS + backend + TLS mode. No vibe claims. | `onyx-server-perf` | all | Bench artifact committed or attached to the tag notes |
| **PX-6** | **Fan-out and `ConnState` cost (Linux first).** P-03 / P-04 / P-05 from the Q4 plan: shrink `ConnState` without changing capsule shape; measure channel fan-out; right-size `DeliverBuf`. Port the wins; do not special-case Linux arithmetic into the portable backend. | `onyx-server-perf` | linux then others | `zig build bench` before/after |

**Accept for the track:** a contributor can `zig build` a node for Linux,
Windows, and at least one BSD; the Linux node still hot-upgrades; Windows/BSD
nodes speak the same IRCX and reject Helix USR2 rather than corrupting state;
bench numbers exist for each backend.

**Anti-pattern:** shipping a Windows binary that links the io_uring loop
behind a stub that panics, or claiming “portable” because `platform.zig`
compiles.

## 5. Track KX — kernel unique features (Linux / BSD / Windows)

**Goal:** the daemon takes each kernel's *actual* unique feature set —
I/O, TLS offload, listen-path, secret memory, sandbox, observability —
and fail-closes when a Linux-only path is reached on BSD/Windows (and
the reverse). PX owns the portable `IoBackend` trait. **KX owns the
OS-specific wins that must not be flattened into a lowest-common
denominator.**

Every KX item answers three questions before dispatch: (1) does live
source already do it (§2 table)? (2) does it rewrite Helix buffer /
fd ownership (if yes → deferred with PX-4 / multishot)? (3) who
probes at boot so a missing kernel feature is a log + fallback, never
a panic?

Default-off or probe-then-enable. Byte-identical when the feature is
off or the kernel lacks it.

### 5.1 Linux — take the remaining Ringlane / net / LSM wins

Linux already has the production reactor, kTLS, `SO_REUSEPORT`,
`eventfd`, sealed `memfd`. KX-L is everything else that helps *this*
IRC/IRCX mesh daemon without reopening deferred io_uring ownership.

| ID | Item | Why it helps this server | Owner | Gate |
| --- | --- | --- | --- | --- |

| **KX-L6** | **kTLS leftovers (Linux ULP only).** (a) RX rekey: `setsockopt(TLS_RX)` after a verified KeyUpdate instead of closing the conn. | **KX-L8** | **Secret pages.** `MADV_DONTDUMP` + `MADV_WIPEONFORK` on ticket-key / MeshPass / session-token arenas; `mlock` (or `MCL_ONFAULT`) for the live ticket key; `PR_SET_DUMPABLE=0` in production; probe `MFD_SECRET` / `MFD_NOEXEC_SEAL` for Helix if the kernel has them. ### 5.2 FreeBSD — kqueue, reuseport-LB, Capsicum, kernel TLS

FreeBSD is the richest BSD for this daemon. PX-3 is the kqueue loop.
KX-B is what Linux `SO_REUSEPORT` / Landlock / kTLS look like *here*.

| ID | Item | Why it helps | Owner | Gate |
| --- | --- | --- | --- | --- |
| **KX-B0** | **kqueue contract (PX-3 depth).** `EVFILT_READ`/`WRITE` + `EVFILT_TIMER` + `EVFILT_USER` (replaces Linux `eventfd`) + `EVFILT_EMPTY` / `NOTE_LOWAT` for send-buffer drain + `EV_DISPATCH`/`EV_CLEAR`/`EV_ONESHOT` so a filter cannot fire into a freed `ConnState`. `EVFILT_PROCDESC` when Capsicum/pdfork is on. | Correct completion semantics; no Linux eventfd on BSD. | `onyx-server-reactor` | kqueue unit tests; cross-compile `x86_64-freebsd` |
| **KX-B1** | **`SO_REUSEPORT_LB`.** FreeBSD's load-balancing reuseport is **not** Linux `SO_REUSEPORT`. Bind per-shard listeners with `_LB` so accepts spread; plain `SO_REUSEPORT` on FreeBSD is “first socket wins” and will starve shards. | Without this, PX-3 on FreeBSD is a single-core accept path. | reactor · integrator (BSD listen helper, not `reuseport.zig`'s Linux syscall) | two-listener accept-spread test |
| **KX-B2** | **FreeBSD kernel TLS (optional).** FreeBSD KTLS UAPI ≠ Linux `TCP_ULP`/`SOL_TLS`. Default remains userspace Armor. If probed, TX-only on TLS 1.3 AES-GCM, same drain-before-attach + USR2 “offloaded marker” rules as Linux. Fail closed on UAPI mismatch. Do not share `src/daemon/ktls.zig` structs with FreeBSD. | Same CPU win as Linux kTLS on a FreeBSD node. | `armor-tls` | skip-if-no-ktls; never run Linux vectors on BSD |
| **KX-B3** | **Capsicum + Casper + `pdfork`.** After listen/bind/open, `cap_enter`; limit each client fd to `CAP_READ`/`CAP_WRITE`/`CAP_EVENT`/`CAP_SHUTDOWN`. Casper only for the services the daemon still needs post-enter (DNS, syslog). `pdfork`/`procdesc` for the supervisor instead of pidfd. | Strongest BSD sandbox; stolen process cannot `connect()` a new peer. | hardener | Capsicum skip-if-ENOSYS test |
| **KX-B4** | **Accept filter + TCP function block.** `accept_filter` `dataready` (not `httpready`) so a `ConnState` is not allocated until the first byte. Optional `TCP_FUNCTION_BLK` `bbr`/`rack` — measure, default off. | SYN flood / empty-connect admission is a Warden problem the kernel can cheapen. | integrator · warden | listen-option test |
| **KX-B5** | **Helix without memfd.** `shm_open`+`unlink` sealed by `ftruncate`+`write`+`fcntl` locks, or a `pipe`+`SCM_RIGHTS` one-shot. **Fail closed** if a Linux memfd path is compiled in. Document: USR2/`execve` capsule handoff is Linux; FreeBSD 0.7 is cold-upgrade or this equivalent. | PX-4. A fake memfd on BSD is a security bug. | `onyx-session` | `test-helix` skip/fail-closed on non-Linux |

### 5.3 OpenBSD — pledge, unveil, pinsyscalls

OpenBSD has no io_uring, no kTLS, no Landlock, no `eventfd`, no `memfd`.
The win is the **mandatory** sandbox and a correct kqueue.

| ID | Item | Why it helps | Owner | Gate |
| --- | --- | --- | --- | --- |
| **KX-O1** | **`pledge` profiles.** Daemon: `stdio inet unix rpath wpath cpath flock unveil`. ACME worker: `stdio inet rpath wpath`. `armor` CLI: `stdio rpath wpath` (or `stdio rpath` when stdout-only). Tighten after listen. A missed promise is a crash — write the promise list from the live syscall set, not from memory. | This is OpenBSD's reason to exist as a node OS. | hardener · `armor-tls` | `test-cli` + a pledge-fail test that a disallowed `connect` kills the helper |
| **KX-O2** | **`unveil`.** Unveil only the config, cert/key dir, data dir, and `/dev/urandom` (or `getentropy`). `tcpserver` listen paths need no unveil of `$HOME`. `armor` unveils `-in`/`-out`/`-CAfile` only. | Path-equivalence of Linux KX-L9. | hardener | unveil skip on non-OpenBSD |
| **KX-O3** | **`pinsyscalls` + W^X.** Honor OpenBSD's pinned-syscall policy; do not `mprotect` RWX for WASM in the daemon process (OroWasm stays a helper or is off). | Stops a JIT-style escape we do not need. | hardener | documented; `test-helix` does not map RWX |
| **KX-O4** | **kqueue + Helix.** Same KX-B0 filters that exist on OpenBSD (`EVFILT_USER` yes; `EVFILT_PROCDESC` / `_LB` / KTLS **no**). Helix = KX-B5 cold path. `closefrom` after exec. | Honest port, not a Linux subset that traps. | reactor · session | cross-compile + skip tests |

### 5.4 NetBSD / macOS / Darwin

## 9. Track HX — harden, exploit hunt, correctness polish

**Goal:** every adversary-reachable parser and reflected field has a
fail-closed test. Findings are patched, not ticketed-and-forgotten.
Classification (P0-5) is the inventory; HX is the hunt.

### 9.1 Hunt method (mandatory)

1. Pick one trust boundary (client→daemon, daemon→daemon, daemon→OS,
   browser render).
2. Name the entry (`parseLine`, handler, mesh frame, `innerHTML` sink).
3. Construct a concrete counterexample (bytes or UI action).
4. If reachable: write `test "exploit: …"` (or client vitest) that **fails**,
   then patch until it passes. No exploit PoC outside the suite.
5. Fresh reviewer on session / TLS / mesh / render sinks.

Do not “audit by adjective.” A finding without a path and a file is not a
finding.

## 11. Exit criteria (major 0.7)

All of the following, or a dated written cut with owner and reason:

1. **Original P0-0…P0-6** closed (Helix bridge, bench, io flags or documented
   integrator remainder, `test-dst`, TLS harden, exploit inventory, version).

   one BSD triple compile; USR2 is Linux-only and fail-closed elsewhere.
3. **KX-X1** boot matrix is true on Linux; **KX-L2** listen/TCP knobs landed
   or waived; FreeBSD listen path is `_LB` or explicitly “single listener”;
   OpenBSD `armor` has a pledge/unveil profile or a dated skip; no kTLS
   claim on Windows; deferred io_uring ops still deferred.
4. **AX-0 and AX-1** green (`armor ocsp` / `armor crl` verify fail-closed);
   **AX-2** loopback `s_client` or a dated waiver; `enc` still exit 3.

   cannot smuggle a line.
6. **CX-1…CX-4 and CX-6** shipped in Onyx (LISTX, MODEX, WHISPER compose,
   PROP settings, ACCESS finish).
7. **HX-1, HX-2, HX-11** green; `test-exploit` and client XSS cases cite new
   coverage, not just old counts.
8. **TLS roadmap** remains complete; no reopened cut items.
9. **Full `zig build test` count** + `pnpm typecheck && pnpm lint && pnpm test`
   recorded. Linux USR2 0.5.8→0.7 rehearsal. No deploy without an explicit go.
