## Grounded starting point

The terminal setup offers private, community and media profiles, help/search, nonsecret setting changes, review and cancellation; bundle publication has a separate actual-material review ([main.zig](../../src/main.zig#L1023), [setup guide](../guide/setup.md#L210)). Linux draft/export publication uses owner-only new files and refuses replacement; resume validates privacy and format, and changes since explicit save are not autosaved ([setup guide](../guide/setup.md#L219)). Color is conditional on terminal and environment; redirected output is plain ([setup guide](../guide/setup.md#L253)). The current-source artifact passed a six-check wizard PTY/save/resume/redirected pilot ([ledger](../ops/roadmap-acceptance-ledger-2026-10-26.md#L167)); this is not screen-reader or whole-wizard accessibility acceptance.

## Proposed flows and acceptance

1. **Choose a purpose.** Present “Connect to a network”, “Recover access”, and “Set up a server I own” as distinct journeys. Copy: “Connecting lets you join an existing network. Setting up a server creates an operator configuration; it does not enroll a node in an existing mesh.” A novice can choose the appropriate path without being asked to own a server or create an account unnecessarily. Owned-server setup reuses the server's actual profile labels and plan; an existing-network enrollment path stays explicitly unavailable until its contract exists ([ledger W01/W07](../ops/roadmap-acceptance-ledger-2026-10-26.md#L19), [setup guide](../guide/setup.md#L59)).

2. **Save and return privately.** Copy: “Save a private checkpoint. Changes after this save are not included.” Show the chosen destination and what is saved before confirmation; do not request credentials in the interactive prompt or place them in URLs, history, analytics, or ordinary settings. On return, show restored nonsecret choices and revalidate; if the file is unsafe or invalid, explain the rejection and a safe next step without revealing contents. A second checkpoint uses a new path; cancel leaves live configuration untouched. Test interruption before and after save, unsafe file rejection, and resumed validation against current settings ([setup guide](../guide/setup.md#L210), [client outline](onyx-client-integration-2026-10-26.md#L68)). Client-side storage mechanism remains a design decision, not a claim that the server's Linux file guarantees automatically apply to it.

3. **Recover from validation.** Show the affected field, a bounded explanation, and the next action; retain other choices and return the user to editing. Example proposed copy: “This port is invalid. Enter a port in the allowed range and review again.” For a trust failure: “The server identity could not be verified. Check the address and trusted certificate with your administrator.” Never suggest disabling verification as the default. Acceptance: an invalid candidate cannot publish; correction and review succeed without starting a listener or changing live configuration. Use the authoritative loader and redacted diagnostics, not a separately invented client validator ([main.zig](../../src/main.zig#L1206), [ledger W11/Q01](../ops/roadmap-acceptance-ledger-2026-10-26.md#L29)).

4. **Equal access to every step.** Provide visible progress, meaningful headings, help and back/review paths; color reinforces text rather than carrying meaning. At narrow width, long values remain readable and actionable. Keyboard-only users can reach, understand and complete every action; screen readers receive names, ordering, status and validation errors; high contrast and reduced motion preserve the same task. Test full color, `NO_COLOR`, dumb and narrow terminals, redirected/headless equivalent choices, keyboard traversal and actual assistive technology. Record environment and results; the existing PTY pilot alone cannot close W02 ([ledger](../ops/roadmap-acceptance-ledger-2026-10-26.md#L19), [setup guide](../guide/setup.md#L253)).

5. **Finish with separate evidence.** Proposed copy: “Configuration validated. Connection, chat, and media have not yet been verified.” After actual checks, report each observed state separately, with unknown or failed states and a next step. A working chat connection must not imply that microphone permissions, media transport or rendering work; a configured media port is not a media test. Optional soundcheck must be private and only offered when supported. Acceptance records the check and result for each claim, and leaves unknowns visible ([setup guide](../guide/setup.md#L83), [readiness](../guide/setup.md#L269), [ledger V01/W08](../ops/roadmap-acceptance-ledger-2026-10-26.md#L26)).

6. **Keep participant continuity.** When a negotiated, supported host-change notification arrives, update the existing participant's visible host without a duplicate participant, false disconnect, or lost conversation history. Proposed quiet detail: “Visible host updated.” Preserve a historical event's recorded host separately from current identity; do not infer that a cloak erases prior observation. Exercise login and rotation, repeated updates and peers without the capability against real client/server fixtures, including compatibility behavior; do not invent a fallback or wire operation ([client outline](onyx-client-integration-2026-10-26.md#L85), [capability reference](../reference/ircv3-capabilities.md#L41), [historical identity](onyx-client-integration-2026-10-26.md#L289)).
